- `rows=4096`

- `baseline`: global gather -> global dense

## Disassembly

Generated by:

```bash
/opt/rocm/bin/roc-obj -d -o experiments/rdna3_gather/isa experiments/rdna3_gather/.torch_ext/rdna3_gather_ext_d0.so
```

Files:

- `isa/rdna3_gather_ext_d0.so:1.hipv4-amdgcn-amd-amdhsa--gfx1100`
- `isa/rdna3_gather_ext_d0.so:1.hipv4-amdgcn-amd-amdhsa--gfx1100.s`

Observed instruction paths:

- `gather_global_kernel`: `global_load_b32` + `global_store_b32`, no LDS path.
- `gather_vgpr_lds_kernel`: `global_load_b32` -> `ds_store_b32` -> `s_barrier` -> `ds_load_b32` -> `global_store_b32`.
- `gather_direct_lds_kernel` default build: zero-fill `ds_store_b32`, then fallback `global_load_b32` -> `ds_store_b32` -> `s_barrier` -> `ds_load_b32` -> `global_store_b32`.
- No `buffer_load_dword ... lds` or `raw.buffer.load.lds` appears in the default build.

Resource metadata from `llvm-readelf --notes`:

- `gather_global_kernel`: `vgpr_count=20`, `sgpr_count=44`, `vgpr_spill_count=0`, `sgpr_spill_count=0`, `private_segment_fixed_size=0`, `wavefront_size=32`.
- `gather_vgpr_lds_kernel`: `vgpr_count=21`, `sgpr_count=36`, spills 0, dynamic LDS arg present, `wavefront_size=32`.
- `gather_direct_lds_kernel`: `vgpr_count=21`, `sgpr_count=36`, spills 0, dynamic LDS arg present, `wavefront_size=32`.

## Direct-to-LDS Probe

The opt-in inline asm probe does not compile on the current target:

```text
error: invalid operand for instruction
buffer_load_dword v3, s[16:19], 0 offen lds;
```

The earlier CK/raw intrinsic route also failed in backend selection (`llvm.amdgcn.raw.buffer.load.lds` could not be selected).

## Decision

Do not spend the next iteration chasing direct-to-LDS ISA syntax.

Phase 1 shows that gather-to-LDS alone is slower than direct global gather for this copy-out workload, and the direct-to-LDS probe is not currently a valid gfx1100 inline-asm path. Keep the direct path as an opt-in ISA experiment only.

The next useful step is Phase 2: fuse a small compute consumer after densification and test whether LDS staging pays for itself when the dense tile is reused locally. The pass/fail criterion should be end-to-end fused latency, not the standalone gather-to-LDS copy.
